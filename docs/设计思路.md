# 设计思路

## 1. 问题定义

我们要解决的不是「隐私」问题，而是**「人机阅读难度不对称」**问题。

给定同一段密文：

- 人类应当：看得见、看不懂、记不住、猜不出、还原不了
- AI 应当：读得到、解得开、无额外负担

这两件事在同一个符号串上同时成立，才有讨论价值。

## 2. 威胁模型

| 攻击者 | 已掌握 | 手段 | 结果 |
|---|---|---|---|
| 人类·肉眼 | 密文 | 直接看 | 无法建立符号↔语义映射 |
| 人类·装字体 | 密文 + 字形 | 观察图形 | 图形可辨但无语言线索 |
| 人类·统计 | 大量密文 | 频次分析 | 中文单字频率 + 上下文歧义使猜测空间爆炸 |
| 人类·暴力 | 密文 | 枚举上下文密钥 | 密钥是自然语言短语且**换轮即废**，不可行 |
| 机器·有密钥 | 密文 + 密钥 + 池子 | 查表 | 秒级破解（**设计如此**） |
| 机器·无密钥 | 密文 + 池子 | 上下文/语义先验 | 常见表达可猜出大意（**设计如此**） |

关键：**后两行是 feature，不是 bug。** 本方案从未打算对抗机器。

## 3. 不对称的来源

### 3.1 记忆容量

人类工作记忆 4–7 个组块。面对 100 万符号池，即使每秒记 1 个、不遗忘，也需要 11.6 天不间断，且毫无冗余可用。

### 3.2 上下文带宽

「意义由上下文赋予」意味着：要解密，必须先还原**当轮那个上下文**。而上下文是自然语言的：

- 可能是 `"今晚聊游戏"`
- 可能是 `"工作群 讨论排期"`
- 也可能是 `"那件事"` —— 只有当事人知道指什么

攻击者要么枚举，要么偷听上下文。**而偷听上下文等于偷听明文对话本身**，本方案把安全性锚定在「上下文不外泄」上。

### 3.3 换轮即废

一次性密钥（OTP）的思想在这里被弱化使用：

```
轮次 n：  K_n → 映射表 M_n = 确定性派生(K_n, 池)
```

`M_n` 的不确定性量级为 `|池|!`（排列数）。即使 `M_1` 完全泄露，对 `M_2` 的帮助为零。

不同于 OTP 的是：这里不保证信息论安全，只保证**人类侧不可行 + 机器侧需要上下文**。

## 4. 设计取舍

### 4.1 定长 vs 变长

- **变长**（前缀码 / 分隔符）：池子利用率高，但密文需要分隔符或前缀判定 → 人类能靠分隔符切块，且实现复杂
- **定长**（本方案）：`符号 = 1 基字 + M 叠加符`，字符长度恒为 `1+M`；密文按固定长度切分，无分隔符

代价：牺牲了单码位符号与组合符号的混用（混用会破坏定长）。收益：解码零歧义、实现极简。

### 4.2 加密 vs 编码

本方案**不做任何数学加密**：

- 不做替换表保密（表由密钥派生，本身不存储）
- 不做扩散/混淆（无雪崩效应）
- 不做完整性校验（无 MAC）

原因：目标是对抗人类带宽，不是对抗算力。真正的保密性应在内层用标准密码学解决（见 README 的「它不是密码学」一节）。

### 4.3 可渲染 vs 不可渲染

私用区码位没有标准字形，人类看不到。两个选择：

- **不造字**：人类看到豆腐块 □ —— 更"不可读"，但也失去了「看得见却看不懂」的展示性，且无法出现在任何正常文本流里
- **造字**（本方案）：程序化生成互不相同的图形 → 人类能看见、能区分、但无法记忆

我们选造字，因为**「看得见但读不懂」比「看不见」更符合设计意图**，也更容易向人解释这套体系。

## 5. 与密码学叠加的推荐形态

```
明文
 └─ AES-256-GCM（真正的保密性 + 完整性）
     └─ Base64 / 二进制
         └─ AICryptLang 编码（对抗人类阅读）
             └─ 密文符号串
```

外层负责挡住人类，内层负责挡住机器。两层正交，互不干扰。

## 6. 已知边界

1. **不能对抗机器**：这是设计目标，不是缺陷。
2. **上下文泄露 = 全盘失效**：密钥源于上下文，上下文被听到即等于明文被听到。
3. **渲染依赖字体**：私用区符号必须安装自造字体，否则为豆腐块。
4. **复制粘贴易失真**：组合序列含大量叠加符，某些编辑器/平台会做 NFC/NFD 归一化或丢弃孤立叠加符 → 传输前建议先做一次往返校验。
5. **单元长度有限**：受池子大小与字符集大小约束（当前实现上限 8）。
