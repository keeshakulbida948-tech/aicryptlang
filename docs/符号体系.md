# 符号体系

## 总览

```
┌─────────────────────────────────────────────────────────┐
│ 第 3 层  字形层   Glyph    —— 人类眼睛看到的图形         │
```

## 第 1 层：码位池

符号的「本体」是 Unicode 码位。可用池子：

| 池子名 | 范围 | 规模 | 典型归属 |
|---|---|---|---|
| `PUA` | U+E000–U+F8FF / U+F0000–U+FFFFD / U+100000–U+10FFFD | 137,468 | 私用区（无标准字形） |
| `CJK-ExtA` | U+3400–U+4DBF | 6,582 | 汉字扩展 A |
| `CJK-ExtB` | U+20000–U+2A6DF | 42,720 | 汉字扩展 B |
| `CJK-ExtC–ExtH` | U+2A700–U+323AF | ~48,000 | 汉字扩展 C–H |
| `LinearB` | U+10000–U+1007F | 128 | 线形文字 B |
| `Cuneiform` | U+12000–U+123FF | 1,024 | 楔形文字 |
| `Hieroglyph` | U+13000–U+1342F | 1,072 | 埃及圣书体 |
| `Musical` | U+1D000–U+1D1FF | 512 | 乐谱符号 |
| `Alchemical` | U+1F700–U+1F77F | 128 | 炼金术符号 |
| `MathOps` / `Arrows` / `Dingbats` … | 各类符号区 | 数千 | 数学/箭头/装饰 |

**过滤规则（必须）**：剔除代理区 `U+D800–DFFF`、非字符 `U+FDD0–FDEF` 与每平面 `xFFFE/xFFFF`、控制/格式/分隔类 `Cc Cf Cs Zl Zp`、以及未分配 `Cn`（不稳定，随时变）。

## 第 2 层：组合序列

### 结构

```
符号 = 基字(base) + M 个叠加符(combining marks)
     = 1 + M 个码位
```

**长度恒定是硬约束**：密文不允许携带分隔符，解码只能按固定字符长度切分。

### 空间计算

```
理论空间 = |基字池| × |叠加符池|^M
```

| 基字池 | 叠加符池 | M | 理论空间 |
|---|---|---|---|
| 33,894 (CJK基本区 + 扩展A + BMP私用区) | 2,408 (全 Unicode 组合标记) | 2 | 196,521,541,888 |
| 33,894 | **360（按本机字体过滤后可渲染）** | 2 | **4,392,403,200** |
| 33,894 | 360 | 3 | 1,581,265,152,000 |

### 为什么要按字体过滤叠加符

叠加符（combining marks）在全 Unicode 里有 2,408 个，但**本机字体只覆盖其中 360 个**。
若不过滤：

- 人类看到的组合符号会「只剩基字」，叠加符是不可渲染的豆腐块或直接被丢弃
- 视觉效果退化成「一堆重复的汉字」→ 失去符号区分度

过滤实现：把候选字体（msyh / simsun / simsunb / mingliub / NotoSansSC / arial / times / seguisym …）的 cmap 求并集，只保留落在并集里的标记。

### 排除变化选择符

`U+FE00–FE0F`、`U+E0100–E01EF` 是**变化选择符**（variation selectors），类别是 `Mn`，但**本身不可见**，混进池子会让符号显示异常。必须排除。

## 第 3 层：字形层（自造字）

### 为什么必须自造

私用区码位在任何标准字体里都没有字形 → 显示为豆腐块 □。
而且 **PUA 不在操作系统的字体回退链里**：装一个只覆盖部分 PUA 的字体，其余 PUA 码位依然是豆腐块。
所以要么不用 PUA，要么**全量覆盖**。

### 造字算法

```
对每个码位：
  1. 在 9×9 网格上随机取 4–7 条线段（端点量化到格点，偏好正交/短对角线）
  2. 每条线段 → 展开成"有厚度的四边形轮廓"（零面积线段渲染不可见）
  3. 以 25% 概率追加 1 个实心块（方/三角/六边）
  4. 计算该字形的签名（线段+块的有序元组），签名重复则重掷 → 保证不重样
  5. 轮廓方向统一为顺时针（TrueType 填充规则）
```

参数：`unitsPerEm = 1000`，内容区约 `70–830`，笔画粗细 `62`，步进宽度 `1000`。

### 打包与分片

用 `fontTools.fontBuilder.FontBuilder` 组表：

```python
fb = FontBuilder(1000, isTTF=True)
fb.setupGlyphOrder(...); fb.setupCharacterMap(cmap); fb.setupGlyf(glyphs)
fb.setupHorizontalMetrics(...); fb.setupHorizontalHeader(...)
fb.setupNameTable(...); fb.setupOS2(...)
fb.setupPost(); fb.font["post"].formatType = 3.0   # ← 字形数多时必须
fb.save(path)
```

**两个硬限制：**

| 限制 | 原因 | 解法 |
|---|---|---|
| 单文件最多 65,535 字形 | `maxp.numGlyphs` 是 uint16 | 按平面分片：BMP / 平面15 / 平面16 |
| post 表索引溢出 | format 2.0 用 uint16 存字形名索引 | `formatType = 3.0`（不存名字） |

### 最终产物

| 字体 | 覆盖 | 字形数 | 体积 |
|---|---|---|---|
| `AICryptLangBMP.ttf` | U+E000–U+F8FF | 6,400 | ~0.6 MB |
| `AICryptLangP15.ttf` | U+F0000–U+FFFFD | 65,534 | ~5.8 MB |
| `AICryptLangP16.ttf` | U+100000–U+10FFFD | 65,534 | ~5.8 MB |
| **合计** | **137,468** | **137,468** | **~12 MB** |

## 渲染覆盖实测

字体并集（含自造字体）覆盖率：

| 指标 | 数值 |
|---|---|
| 基字覆盖 | **100%** |
| 完整符号覆盖（基字 + 全部叠加符） | **100%** |

> 注意：单个系统字体都不够用。msyh 只覆盖 81% 的基字、0.02% 的完整符号；arial / times 各覆盖约 61% 的标记但 0% 的基字。**必须靠字体回退拼接 + 自造字体补齐。**

## 符号池数据格式

`symbols.json`：

```json
{
  "count": 1000000,
  "seed": 20260920,
  "format": "chars",
  "symbols": ["⠁⃔̄", "䲀ࣔ𝆆", "..."]
}
```

- `format = "chars"`：`symbols` 是字符串数组（大池子用，紧凑）
- `format = "detailed"`：`symbols` 是对象数组，含 `cp`（码位）/ `char` / `name` / `pool`（小池子用，便于分析）

`symbols.txt`：一行一个符号，最便于肉眼翻看（但大池子文件很大，建议用 VSCode）。
