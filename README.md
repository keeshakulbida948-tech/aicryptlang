## 它是什么

一句话：**一套用「符号 + 上下文密钥」承载消息的编码体系，专门让人类读不动、让 AI 读得动。**

三句话：

1. **符号不发明，只采样。** Unicode 现成池子就有 15 万+ 已分配码位、13.8 万私用区码位；再叠加「基字 + 组合标记」的组合序列，理论空间到**十亿级**。
2. **意义不固定，由上下文赋予。** 同一个符号今天表示「明」，明天可能表示「删」。映射表由一句上下文密钥（比如 `"今晚聊游戏"`）确定性派生，**换一句密钥，整张表即废**。
3. **人机不对称。** 人类工作记忆只有 4–7 个组块，面对百万级符号池 + 自然语言密钥空间，只能放弃；而 AI 拿到密钥直接查表，甚至没有密钥也能靠语义先验猜个七八分。

> 它不是要骗过 AI，而是**利用人类上下文带宽的物理极限**，做一层「人类看不懂、AI 毫无障碍」的表达层。

## 核心思路

### 1. 不对称在哪里？

| 能力 | 人类 | AI |
|---|---|---|
| 同时记住的符号数 | 4–7 个组块 | 整个上下文窗口 |
| 记忆百万级映射表 | 不可能 | 不构成问题 |
| 从上下文中还原语义 | 需要大量推理且不稳定 | 本来就是强项 |
| 枚举自然语言密钥空间 | 天量且每条都要人肉验证 | 可以批量试，还能靠语义剪枝 |

所以设计的着力点是：**把人类最弱的两项（记忆容量、上下文带宽）拉到极限。**

### 2. 密钥就是上下文

编码不是「算法 + 密钥」，而是「**上下文 + 派生映射**」：

```
映射表 = 确定性派生( 上下文密钥 K, 符号池 )
密文   = 逐字查表( 明文, 映射表 )
```

- 密钥 K 可以是任意自然语言片段：`"2026-09-20 晚 聊天 话题A"`
- 同一个字，不同 K → 映射到**毫无关系**的符号
- 同一句话，不同 K → 密文**完全不同**
- 密钥不需要另行保管：它就是你们当时在聊的那件事 —— **人走了，密钥就丢了**

### 3. 换轮即废（关键设计）

一次性密钥是密码学的老套路，但这里玩的是「**上下文无痕更新**」：

```
轮次 1：K = "今晚聊游戏"        → 映射表 A
轮次 2：K = "工作群 讨论排期"    → 映射表 B（与 A 完全无关）
```

攻击者即使截获了轮次 1 的密文、并通过某种方式拿到了轮次 1 的映射表，**对轮次 2 也毫无帮助**。而映射表本身有 `|符号池|!` 级别的不确定性，反推出映射表等同于破解一次一密。

## ⚠️ 先说清楚：它不是密码学

必须诚实说明，避免误解：

| 维度 | 本方案 | 现代密码学 |
|---|---|---|
| 对抗对象 | **人类**（带宽/记忆有限） | 攻击者（含机器） |
| 安全性来源 | 符号空间 + 上下文密钥的隐蔽性 | 数学困难问题 |
| 抗机器暴力破解 | ❌ 不保证 | ✅ 提供可证明的界 |
| 依赖密钥保密 | ✅ 强依赖 | ✅ |
| 前向保密 | 靠「换轮」近似实现 | 协议层实现 |

**结论：AICryptLang 是「编码 / 混淆 / 隐写」层，不是加密层。**
需要真正的保密性时，请**先加密再套本方案**：`AICryptLang( AES-GCM(明文) )`。这样外层负责挡住人类，内层负责挡住机器。

## 符号体系（三层）

```
┌──────────────────────────────────────────────┐
│  第 3 层  字形层   —— 人类眼睛看到什么        │
│  程序化造字 → 打包字体（私用区全量 13.7 万）  │
├──────────────────────────────────────────────┤
│  第 2 层  组合层   —— 怎么把池子做大          │
│  1 基字 + M 叠加符，定长，空间 = |基|×|标|^M  │
├──────────────────────────────────────────────┤
│  第 1 层  码位层   —— AI 真正读到的东西       │
│  PUA / CJK 扩展 / 古文字 / 符号，共 15 万+    │
└──────────────────────────────────────────────┘
```

### 第 1 层：码位池（现成，不发明）

| 池子 | 范围 | 规模 | 有字形？ |
|---|---|---|---|
| 私用区 PUA | BMP + 平面 15/16 | 137,468 | ❌ 需自造 |
| CJK 扩展 A–I | U+3400–U+323AF | ~10 万 | ✅ 大字体可显示 |
| 古文字 | 楔形/圣书体/线形文字B/乐谱… | 数千 | ✅ 部分 |
| 数学/技术/装饰符号 | 各类符号区 | 数千 | ✅ |

### 第 2 层：组合序列（把池子拉到十亿级）

```
符号 = 基字(1 码位) + 叠加符(M 码位)      ← 长度恒定为 1+M
```

- 基字池：33,894（CJK 基本区 + 扩展 A + BMP 私用区）
- 叠加符池：按**本机字体可渲染**过滤后 360 个
- M = 2 时空间 = `33,894 × 360²` = **4,392,403,200**

**为什么必须定长？** 密文传输时不带分隔符，解码只能按固定字符长度切分。一旦混入长度不一的符号，切分就会错位 → 强制「全组合序列」模式，保证每个符号都是 `1+M` 个码位。

### 第 3 层：字形层（真正要开发的部分）

私用区码位在任何标准字体里都是豆腐块 □，所以必须自造：

- **算法**：9×9 网格量化 + 随机笔画（线段转成有厚度的四边形轮廓，否则零面积不可见）+ 可选实心块
- **去重**：每字形生成签名，签名重复即重掷 → 保证**字形互不相同**
- **打包**：`fontTools` FontBuilder → TTF
- **分片**：TTF 的 `maxp.numGlyphs` 是 uint16（上限 65,535），13.7 万字形装不下 → 拆成 BMP / 平面15 / 平面16 三个字体文件

## 工作原理

### 编码

```python
seed  = SHA256(密钥 K)[:8]           # 上下文 → 种子
pool  = Random(seed).sample(符号池, |字符集| × 单元长度)
映射表 = { 字符集[i] : pool[i*L : (i+1)*L] }   # 定长 L
密文   = 映射表[明文字符] 依次拼接
```

### 解码

```python
映射表 = 同上的确定性派生（同 K + 同池 → 同表）
逆表   = { 符号串 : 字符 }
明文   = 密文按 符号字符长度 × L 切分 → 逐块查逆表
```

**要点：解码所需的全部信息 = 密钥 K + 符号池。** 没有额外的密钥分发、没有握手、没有状态 —— 这正是「人走了密钥就丢了」的工程含义。

### 一句话示例

```
密钥 K = "今晚聊游戏"
明文   = 明天下午三点，老地方见。带伞。
密文   = 䲀𝅥ࣔ𝆆⳱ؔ۫艗֙࣬聜֚֠҈ֲ環ۭ̇ٓࣸ侼̕҉殡...（135 字符）
回解   = 明天下午三点，老地方见。带伞。   ✅
```

同一个字换密钥 → 密文毫无关系；回解依然正确。

## 快速开始

```powershell
# 依赖：Python 3.10+ / fontTools / Pillow
pip install fonttools pillow

# ── A. 组合序列池（百万级，推荐）──
python src/gen_symbols.py --n 1000000 --composite-ratio 1.0 --composite-marks 2
python src/gen_font.py --full-pua            # 私用区全量分片造字
python src/render_preview2.py                # 出预览图

# ── B. 单码位符号池（10 万级）──
python src/gen_symbols.py --n 100000 --seed 20260920
python src/gen_font.py --n 200000
python src/render_preview.py

# ── C. 编码 / 解码 ──
python src/codec.py selftest                              # 往返自检
python src/codec.py demo
python src/codec.py encode --key "今晚聊游戏" --text "明天下午三点老地方见"
python src/codec.py decode --key "今晚聊游戏" --text "<粘贴密文>"

# ── D. 网页符号查看器 ──
python src/gen_viewer.py
# 然后打开 out/符号查看器.html
```

安装字体：把 `out/AICryptLangBMP.ttf` + `out/AICryptLangP15.ttf` + `out/AICryptLangP16.ttf` 双击安装。
**三个都要装**：私用区不在系统字体回退链里，缺哪个区域哪个区域就是豆腐块。

> 脚本按 Windows 环境编写，字体目录默认 `C:\Windows\Fonts`；其他系统改一下字体目录即可。

## 踩过的坑

完整清单见 [`docs/坑位表.md`](docs/坑位表.md)，几个最有代表性的：

| 坑 | 现象 | 解法 |
|---|---|---|
| TTF 单文件字形上限 | `Value 137469 does not fit in format H for numGlyphs` | maxp.numGlyphs 是 uint16 → 上限 65,535，必须分片 |
| post 表溢出 | `OverflowError: unsigned short is greater than maximum` | 字形过多时 `post.formatType = 3.0`（不存字形名） |
| 私用区无系统回退 | 装了字体仍有豆腐块 | PUA 不在 fallback 链 → 覆盖多少就得装多少 |
| 叠加符不可渲染 | 组合符号看着「只剩基字」 | 叠加符池先按本机字体 cmap 并集过滤 |
| 变化选择符污染 | 隐形字符混入池子变豆腐块 | 排除 U+FE00–FE0F / U+E0100–E01EF |
| 映射池切片越界 | 密文回解失败、单元重复 | 取样数必须是 `|字符集| × 单元长度` |
